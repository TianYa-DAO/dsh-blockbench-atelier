# 像素纹理工作流

1. 先确认目标模型、渲染器和逻辑 UV 尺寸，再确定 PNG 的物理像素尺寸。Blockbench 的逻辑纹理尺寸与存储 PNG 尺寸可能不同；先读模型元数据，不要只凭图片分辨率推断 texel 密度。
2. 对齐图集坐标和 cuboid 各面的 UV，预留足够边缘像素避免采样串色；按目标采样方式验证整数倍缩放，像素风使用最近邻放大。
3. 以有限的主色、阴影、高光和强调色区分体块与材质。局部高对比细节要有形状或材质作用，不要为了“更丰富”而无目的地撒噪点。
4. 透明像素应对应明确的镂空、薄片或覆盖层意图。透明度不能证明材质会发光；发光和透明混合效果必须在目标渲染器中验证。
5. 使用 `mc_texture_analyze` 检查 alpha 数量、可见颜色、可见边界、逻辑/物理尺寸比例和相邻像素色差。统计数据用于发现异常，不是美术质量分数。
6. 修改后回到 Blockbench 检查 UV 接缝、背面、遮挡和整体阅读性，并在目标资源管线内验证透明/发光行为。

## 本地样本证据

7 个匿名样本的图集从 64x64 到 1024x512；6 个样本的逻辑 UV 与 PNG 尺寸一致，另 1 个是逻辑 16x16、物理 160x160。视觉调色包括低饱和灰暗纹理、褐/绿有机色、红黄细节、橙白小型精灵和透明底上的亮绿图案。它们说明素材之间差异很大，不代表固定调色板，也不许可复用原图。

一个样本使用两张 64x64 纹理，另一张存在较多未绑定纹理面的记录。应在项目自己的模型中逐面核对引用，而不是假设每个面都有有效图集区域。

## 真机实测（Blockbench 5.2.2 Desktop，2026-10-19）

以下每条都在真机上复现过，不是推断。

1. **UV 坐标空间是模型逻辑分辨率，不是 PNG 尺寸。** 实测：模型分辨率 16、PNG 64x64 时，面 UV 必须写在 0..16 空间；按 0..64 写会采样到图集范围外，**整个模型渲染成全黑且不报任何错**。一个 16px 的图集格在 16 空间里只占 **4 个单位**。PNG 是逻辑尺寸的整数倍放大（此处 4x）只是 texel 密度，不改变 UV 空间。
2. **`texture.uv_width` 不可信。** 代码里设成 64 并回读确认过，后续 `Canvas.updateAllUVs()` 之后 Blockbench 的有效 UV 空间仍按项目分辨率（16）走。判定方法是实验性的：把所有面 UV 设为 `[0,0,16,16]` 时若显示出**整张图集**，说明有效空间是 16（若空间真是 64，则只应显示左上四分之一）。**写完 UV 必须回到视口确认，不要只信读回的字段值。**
3. **`fromDataURL` 是异步的。** 创建纹理后立刻读 `texture.ctx.getImageData()` 会得到全透明 `[0,0,0,0]`。必须轮询等待（实测约 1 次 350ms 轮询后就绪），否则贴图存在但渲染为黑。
4. **V 轴从图集顶边量，不要翻转。** 翻过一次，结果是每个面都采样到图集下半部未绘制区域，全黑。
5. **`face.uv` 是 4 元素角坐标** `[u1,v1,u2,v2]`；`uv_size` 是派生值，单独写它不生效。
6. **图集布局要逐格探像素验证。** 实测踩到：把两种材质画进同一格（后者覆盖前者）、把装饰画到别的格上。写完图集先按 `getImageData(格中心)` 逐格读回颜色，确认互不相同且符合预期。
7. **调色板对比度要按目标视口验证。** 石质用 `(90,95,98)` 时在 Blockbench 暗视口里读起来接近全黑，调到 `(123,128,132)` 才可读。颜色数值正确不等于渲染可读。

## 本插件能主动发现的

`mc_bbmodel_validate` 会检查两类与本清单直接相关的问题：`UV_SPACE`（`texture.uv_width`/`uv_height` 与项目分辨率不一致——这正是导致全黑的陷阱）与 `UV_BLANK`（面采样区域全透明，渲染成洞）。它**不能**判断扁平色块是否是"未绘制背景"还是有意为之，这类要人眼看视口。

## 边界

插件不会复制或上传被分析图像。颜色统计只描述像素分布，不理解材质、风格、光照或语义；alpha 数值、颜色鲜艳度与文件名都不能单独证明游戏中的发光效果。输出 PNG 是否正确还取决于 UV、纹理过滤、材质与目标引擎设置。

## 大图集 + 逻辑分辨率（实测）

1. 128x128 图集配项目分辨率 16 时，**每个逻辑单位 = 8 像素，16px 材质格只占 2 个逻辑单位**；UV 要写 `[格*2, 0, 格*2+2, 2]`。
2. 单个面**占满整块材质格**时不要按面尺寸换算 UV，否则细节被拉扁。
3. 竖直方向拉伸无法避免，所以材质格要按"竖向渐变"来画（顶部亮、底部暗），拉伸后反而自然。
4. 高光画在格子的左/上边缘，暗部画在右/下边缘，任何面朝向上都会呈现体积感。
